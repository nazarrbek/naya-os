# NAYA BALLOONS — CRM

Заказы, склад, гелий и деньги NAYA BALLOONS. Веб-приложение для iPhone и компьютера: его можно добавить на главный экран как приложение. Два личных входа и общая база, изменения появляются у второго владельца сразу.

## Как устроено

| Часть | Технология |
|---|---|
| Приложение | React + TypeScript + Vite, PWA (`web/`) |
| База, вход, фото, мгновенные обновления | Supabase: Postgres, Auth, Storage, Realtime (`supabase/`) |
| Хостинг | Cloudflare Workers (статические файлы, `web/wrangler.jsonc`) |
| Резервные копии | GitHub Actions каждую ночь, зашифрованная выгрузка (`.github/workflows/backup.yml`) |

### Главные правила учёта (в базе, `supabase/migrations`)

- **Одна запись = все связанные проводки, одной транзакцией.** Каждая функция (`save_order`, `issue_order`, `record_expense`…) принимает `p_request_id`, поэтому повторное нажатие или повтор запроса не создаёт вторую запись.
- **Выручка** признаётся в момент «Заказ выдан». **Деньги** меняются в день оплаты, поэтому предоплата сразу попадает на счёт.
- **Материалы списываются один раз:** при «Собрать заранее» или при «Выдан». `sync_writeoff` приводит списание точно к составу заказа, так что повторный вызов ничего не делает. Если состав изменили после сборки, проводится только разница.
- **Покупка для конкретного заказа** идёт в себестоимость этого заказа по своей цене. В среднюю цену склада она не попадает, лишнее уходит на склад.
- **Печать и услуги для заказа** (`order_costs`) входят только в себестоимость заказа: не в склад и не в расходы бизнеса.
- **Гелий:** у каждого производителя шара своя норма с источником (замер > своя оценка > шпаргалка > старая таблица). Пока заказ не выдан, гелий для цены считается по плановой цене за литр (27 ₸). При выдаче берётся средняя цена заправок. Кнопка «Баллон пуст» сверяет списанные литры с баллоном.
- **Личные траты и «взять себе»** — это выплаты владельцам, а не расходы. Внесения — капитал, а не выручка.
- **«Можно забрать себе»** = меньшее из двух сумм: (деньги − резервы) и (прибыль с даты запуска − уже полученное). Делится по долям с учётом того, кто сколько уже получил.
- Журналы денег и склада только дополняются. Исправления видны в истории (`audit_log`) вместе с причиной.

## Локальный запуск

```bash
supabase start -x vector          # нужен Docker
supabase db reset                 # схема + каталог + тестовые владельцы
cd web && cp .env.example .env.local   # вписать ключи из `supabase status`
pnpm install && pnpm dev
```

Тестовый логин: `SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_SECRET_KEY=... node scripts/create-login.mjs ayanat@example.test <пароль>`.

Тесты учёта (pgTAP):

```bash
PGPASSWORD=postgres psql -h 127.0.0.1 -p 54322 -U postgres -d postgres -f supabase/tests/ledger.test.sql
```

## Запуск в работу

1. **Supabase.** Создайте проект (регион — Франкфурт или ближайший). Затем:
   ```bash
   supabase link --project-ref <ref>
   supabase db push                       # миграции
   psql "$DB_URL" -f supabase/catalog.sql # каталог и нормы гелия
   ```
   В Auth → Providers → Email отключите регистрацию («Allow new users to sign up» = off).
2. **Перенос из таблицы.** Финансовые данные в git не попадают:
   ```bash
   uv run scripts/import_sheet.py --xlsx "NAYA BALLOONS — финансовая и складская система.xlsx" \
     --owner "Назарбек=<почта>" --owner "Аянат=<почта>" \
     --launch 2026-11-10 --opening "Kaspi=26446" --opening "Наличные=41000"
   psql "$DB_URL" -f private/import.sql
   ```
   В конце скрипт сверяет контрольные суммы: 11 заказов из Excel, 152 640 ₸ выручки, 67 279 ₸ материалов, 500 ₸ прочих расходов, продажи из Google Sheets, деньги на старте. Если хоть что-то не сходится, импорт отменяется целиком.
3. **Логины:** `node scripts/create-login.mjs <почта> <временный пароль>` для каждого владельца.
4. **Склад на старте:** в приложении «Склад → Пересчитать склад» (`/stock/count?opening=1`).
5. **Приложение:**
   ```bash
   cd web
   VITE_SUPABASE_URL=https://<ref>.supabase.co VITE_SUPABASE_PUBLISHABLE_KEY=<publishable key> pnpm build
   npx wrangler deploy
   ```
   Добавьте адрес приложения в Supabase → Auth → URL Configuration (Site URL).
6. **Резервные копии:** в GitHub → Settings → Secrets добавьте `SUPABASE_DB_URL` и `BACKUP_PASSPHRASE`. Парольную фразу храните отдельно: без неё копию не открыть.

Экспорт всех таблиц в CSV для Excel — в приложении: «Ещё → Экспорт».

## Структура

```
supabase/migrations/   схема, функции проводок, отчёты, права доступа
supabase/catalog.sql   товары, производители, нормы гелия с источниками
supabase/tests/        тесты учёта
scripts/               перенос из таблицы, создание логинов, иконки
web/src/pages/         экраны
```
